# 贡献与 Issue 反馈指南

感谢你愿意帮助改进 Access WeChat Article。本项目涉及微信 PC 客户端窗口识别、本地 MITM、系统代理、SQLite、本地归档和 Playwright 离线缓存。

为了让问题更快被定位，请优先提交结构清晰、信息脱敏、可复现的 Issue。

本文重点说明如何提交 Issue。Pull Request 贡献只保留基本要求。

## 提交 Issue 前

提交前建议先做三件事：

1. 搜索已有 Issue，确认是否已经有人反馈过相同问题。
2. 尽量使用最新代码或最新发布版本复现一次。
3. 准备最小复现信息，不要上传完整数据库、完整日志、证书、Cookie 或含敏感参数的链接。

如果问题只在特定公众号、特定文章或特定时间段出现，请在 Issue 中说明。公众号名、文章短链接、操作步骤和实际结果，通常比一句“不能用”更有帮助。

Issue地址：https://github.com/yeximm/Access_wechat_article/issues

## Issue 标题建议

标题建议使用“页面/功能 + 现象”的格式。

示例：

- `主服务：选择起始日期后主页窗口反复回弹滚动`
- `诊断工具：窗口测试识别到重复文章卡片`
- `离线缓存：带状态 beta 保存后图片未显示`
- `评论采集：评论数量和 HTML 评论数不一致`
- `系统配置：切换菜单后默认开关没有刷新`

不建议使用：

- `有问题`
- `报错了`
- `不能运行`
- `帮忙看看`

## 各类问题需要补充的信息

不同问题需要的信息不一样。可以根据问题类型补充下面内容。

### 主页窗口识别 / 滚动 / 文章卡片问题

请尽量提供：

- 公众号名。
- 当前选择的日期筛选方式，例如不限日期、日期范围、截止日期、起始日期。
- 任务数量。
- 首页当前大概停留在哪个日期。
- 是否出现回弹滚动、滚动不动、重复文章、遗漏文章。
- 诊断工具或主服务日志中的关键几行。
- 脱敏截图，最好包含文章列表、日期组和弹窗结果。

### 文章详情获取问题

请尽量提供：

- 公众号名。
- 文章标题。
- 文章短链接，优先使用 `https://mp.weixin.qq.com/s/...` 这种短链接。
- 是否勾选“跳过已采集记录”。
- 是否打开了系统代理和 MITM。
- 详情获取弹窗中的最终状态。
- 是否捕获到 HTML，还是只捕获到 reference。

### 初始内容存储 / 评论采集问题

请尽量提供：

- 文章目录路径，例如 `storages/公众号名/文章目录`。
- `article_detail.json` 是否存在。
- `origin/main.html` 是否存在。
- 评论结果中的评论数、回复数、页数和停止原因。
- 关键错误日志。

不要直接上传完整 HTML、完整评论 JSON 或完整数据库。必要时只粘贴脱敏后的关键字段。

### 离线缓存 / 图片 / 视频问题

请尽量提供：

- 原始文章短链接。
- 本地 `index.html` 路径。
- 使用的是普通离线归档还是“带状态 beta”。
- 哪类资源异常：图片、GIF、普通视频、视频号卡片、阅读原文。
- 浏览器打开本地页面后的截图。
- 控制台报错或日志中“跳过资源”“下载失败”的关键片段。

如果涉及视频资源，请说明是普通 `<video>` / iframe 视频，还是视频号 `mp-common-videosnap` 卡片。

### 安装 / 启动 / 证书 / 代理问题

请尽量提供：

- 执行的命令。
- 完整错误栈的关键部分。
- 系统代理是否被占用。
- mitmproxy CA 证书是否安装成功。
- `https://mitm.it/` 或 HTTPS 状态检测是否通过。

不要上传 `.mitmproxy/` 目录、证书文件、私钥或系统证书截图。

## 敏感信息脱敏要求

Issue、截图、日志和 PR 中不要包含以下真实值：

- Cookie
- Set-Cookie
- `key`
- `pass_ticket`
- `appmsg_token`
- `uin`
- `wxtoken`
- 完整微信文章 URL 中的临时 query 参数
- SQLite 数据库
- 证书、私钥
- 完整文章归档目录
- 完整评论文件

推荐脱敏方式：

- 长 token 只保留前后少量字符，例如 `abc...xyz`。
- Cookie 只保留字段名，不保留字段值。
- 微信文章链接优先保留短链接；如果必须贴长链接，请删除 `key`、`pass_ticket`、`appmsg_token` 等参数。
- 日志只粘贴能说明问题的几十行，不上传完整日志文件。

## 好的 Issue 示例

````markdown
## 问题描述

主服务选择“起始日期 2026-08-14”后，主页窗口先回弹滚动两次，然后日志提示“日期组快照没有变化”。

## 相关公众号或文章

- 公众号名：人民日报
- 文章链接：暂未打开文章，只在主页列表阶段出现
- 目标日期：2026-08-14

## 操作步骤

1. 打开微信 PC 端公众号主页。
2. 在主服务页面选择“起始日期”。
3. 日期选择 2026-08-14。
4. 任务数量填写 20。
5. 点击“开始运行”。

## 实际结果

主页窗口先发生两次回弹滚动，随后日志提示日期组快照没有变化，检索速度明显慢于窗口测试按钮。

## 期望结果

主流程应复用窗口测试按钮的滚动定位逻辑，快速逼近目标日期，并从目标日期附近开始收录文章卡片。

## 运行环境

- 操作系统：Windows 11
- 启动方式：uv run python dev_server.py
- 微信 PC 版本：待补充
- 是否开启系统代理：程序自动开启
- CA 证书：已安装

## 日志或截图

关键日志：

```text
[14:20:03] WARN 日期组快照没有变化，回弹后仍未发现新日期
```
````

## Pull Request 基本要求

如果你准备提交 PR，请尽量做到：

- 一个 PR 只解决一个明确问题。
- 说明改了哪些功能、影响哪些页面或模块。
- 补充必要测试，或者说明为什么无法本地验证。
- 不提交个人数据、数据库、证书、日志、缓存页面或导出文件。
- 修改用户可见行为时，同步更新相关文档。

本项目涉及本地代理、证书和微信窗口控制。涉及这些能力的改动，请特别说明异常退出时如何恢复系统代理、如何避免关错窗口、如何避免泄露敏感参数。

## 不应提交到仓库的文件

以下内容可能包含个人数据、证书、运行日志、文章材料或短时间有效的请求参数，不应提交到 Git：

- `.mitmproxy/`
- `.playwright-browsers/`
- `data/*.sqlite3`
- `data/sql/*.sqlite3`
- `data/logs/`
- `data/tmp/`
- `data/runtime/`
- `storages/`
- `tests/artifacts/`
- `tests/output/`
- 导出的 `.xlsx`、`.csv`、`.db`、`.sqlite`、`.sqlite3` 文件

如果需要提交测试样例，请使用最小化、脱敏后的假数据。
